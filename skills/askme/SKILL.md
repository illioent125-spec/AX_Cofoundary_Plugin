# askme

사용자가 아무렇게나 말한 아이디어나 문제를, 질문을 던져 분명한 기획으로 만든다. 사용자는 정리된 프롬프트를 쓰지 않아도 된다. 사용자가 이미 말한 것을 더 정확하게 만드는 것이 목적이므로, 사용자가 말하지 않은 새 요구사항이나 기능을 덧붙이지 않는다.

## Workflow

1. **Read**: 이번 대화에서 사용자가 한 말, 붙인 자료, 인자를 읽는다. 말이 두서없어도 그대로 받아들인다. 하려는 일조차 알 수 없을 때만 "무엇을 하고 싶은지 한두 문장으로 말해 주세요"라고 한 번 묻는다.
2. **Find blanks**: 아래 기획 메모의 각 칸을 사용자의 말로 채워 보고, 비었거나 뭉뚱그려진 칸을 찾는다.
   - **모호한 것**: 이 분야 최고 전문가라면 따로 나눠서 정할 텐데, 사용자가 한데 뭉뚱그려 둔 것. 예: "사용자"가 나 혼자인지 팀인지 외부 고객인지, "빠르게"가 1분인지 하루인지.
   - **방법**: 이 일을 할 때 전문가가 실제로 쓰는 도구나 방법론 중 무엇을 쓸지.
3. **Ask**: AskUserQuestion으로 묻는다.
   - 한 번에 최대 3개를 묻는다. 결과를 가장 크게 바꾸는 빈칸부터 묻는다.
   - 선택지는 쉬운 말로 쓰고, 각 선택지에 고르면 무엇이 달라지는지 한 줄로 적는다. 전문가가 아니어도 합리적으로 고를 수 있어야 한다.
   - 방법을 물을 때는 전문가가 실제로 쓰는 것 2~3개를 추천하고, 가장 무난한 것을 첫 번째에 두고 `(추천)`을 붙인다.
   - 이미 답한 것은 다시 묻지 않는다.
4. **Repeat**: 답을 반영해 2번으로 돌아간다. 기획 메모에 빈칸이 없고, 남은 모호한 것이 결과를 바꾸지 않으면 멈춘다. 사용자가 "그만"이라고 하면 바로 멈춘다.
5. **Memo**: 아래 형식으로 기획 메모를 쓴다. 정해지지 않은 칸은 지어내지 않고 `미정`으로 적는다.

   ```
   📝 기획 메모
   - 누가: <쓰는 사람, 받는 사람>
   - 무엇을: <만들거나 하려는 것>
   - 왜: <이걸로 풀려는 문제>
   - 어디까지: <이번에 할 것 / 이번에 안 할 것>
   - 어떻게: <고른 도구나 방법>
   - 정한 것: <질문으로 정한 것을 한 줄씩>
   ```

## Principles

- 질문의 목적은 사용자의 머릿속에 이미 있는 답을 꺼내는 것이다. 사용자가 생각해 본 적 없는 새 방향으로 끌고 가지 않는다.
- 사용자가 모르는 말을 쓰지 않는다. 전문 용어가 꼭 필요하면 괄호 안에 쉬운 말로 풀어 쓴다.
